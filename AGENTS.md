# Working agreement

The user defines one set of website/game work as implementation, meaningful validation, production publication, and live readback. A request to make a feature authorizes completing that set; do not stop at source preparation or a draft PR when publication is possible within the existing authorization. Report a concrete blocker when credentials, a required confirmation, or an external service prevents completion. Do not call a partially deployed feature complete.

Preserve existing game features, source mesh detail, passenger counts, resolution and user saves during performance work. Measure the part actually tested; software WebGL is not a physical GPU or real-device test. The user's earlier administrative closure of physical/audio/real-time checks remains distinct from actual test evidence.

The requested game publication controls permit both verified administrators and the owner to change game visibility without an owner approval request. Authorize every write on the server using the existing account authority; do not trust client roles or local-only flags. Do not broaden other approval workflows as part of this change.

Register newly released games in the shared publication catalog and reuse the current bounded mesh cache and scene recovery when extending route generators.
