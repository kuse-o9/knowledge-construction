# Study Note・鉄道ゲーム・動画編集の点検結果

実施日：2026年10月29日（日本時間）

## 判定

以下に記載した修正を本番へ反映し、検査した範囲は合格しました。全機能の動作保証、すべての脆弱性の発見、実機GPUで全区間の景観を確認したという意味ではありません。

追加の有料プラン・有料AI・有料バックアップは使っていません。既存アカウントの削除、実データを壊す攻撃、他サイトへの侵入、大量通信による負荷試験は行っていません。

## 修正した問題

1. **地形処理の抜け**：地下区間のない路線では地表の切り取りが開始されない条件と、トンネル前後で地表の処理が抜ける条件を修正。共通処理・単独読み込み・あずさ／かいじに適用しました。
2. **線路を覆う補助の床**：長い一枚の床が谷間を横切らないよう、短い間隔と実際の高さの変化点で分割。地上の床は元の地面まで下げ、高架の下を線路の高さまで埋めないようにしました。地下の床・壁・屋根、既存の車両やホームは維持しています。
3. **壊れた動画プロジェクト**：素材とクリップをすべて検証してから開くように変更。無効なファイルの読み込みで、編集中の素材との接続を失う問題を防止しました。
4. **動画の書き出し失敗**：エンコーダーの作成失敗・再生失敗・録画エラー時に、映像取得とタイマーを終了。失敗した録画を完成品としてダウンロードしないようにしました。
5. **権限が切れた後の古い応答**：管理者の不正要求一覧と新しい復元画面では、ログアウトや権限変更より前に始めた通信の結果を表示しないようにしました。

## デッキのバックアップ・復元

- サーバー上の管理者用・個人用デッキと問題が対象です。
- 日本時間でその日最初の変更前、最初の削除前を保存します。同じ日の繰り返し編集で、そのコピーを上書きしません。
- 新しいコピーを保存する際に、30日より古いコピーを整理します。何も保存されない期間に、毎日自動消去する仕組みではありません。
- コピーは合計64MiB・2048件まで。上限またはデータベース400MiB超過時は、古い有効なコピーを消して続けず、対象の変更を中止します。
- 復元は専用パスワード確認済みのオーナー限定。明示確認と編集競合の検査が必要です。
- 復元後は非公開にし、既存の公開停止処分は維持します。アカウントが消えた人のデッキを復活させません。
- 正式なアカウント削除では、その人の個人用コピーも削除します。
- コピーの本文を通常利用者・管理者が直接読む権限はありません。オーナーの画面でも、他人の問題文は一覧に表示しません。
- **同じデータベース内の復旧用コピーです。データベース全体の消失に備える外部バックアップではありません。削除済みの画像ファイル本体、端末内のノート、動画素材、ゲームのセーブは対象外です。**

| 対象 | 結果と方法 |
|---|---|
| 地形の範囲 | 14路線・27方向・10,365地点で、線路周辺が切り取り範囲に入ることを計算検査。実際のGPU描画ではありません |
| JavaScript | 114ファイルの構文検査に合格。ゲームや編集操作すべての成功を意味するものではありません |
| あずさ・かいじ | 両方向の計4運転をCPUで加速検査。全停車駅・通過駅・早発・保存復帰を確認 |
| 車両とドア | 実際のCesiumの形状・行列で4ケース。GPUの映像確認ではありません |
| 車両基地 | 模擬GPUで6件。23階の選択、移動、エレベーター、GPU切断、あずさ・かいじの選択を確認 |
| 読み込み | 通信失敗、時間切れ、破損データ、非公開、キャッシュ、再試行を模擬通信で確認。無限再試行しません |
| 動画編集 | 正常・不正なプロジェクト入力、字幕・映像調整、書き出し失敗／成功の後片付けを検査 |
| 有料AIの停止 | 旧AI処理への要求は停止応答。テスト内の外部AI呼び出し・秘密値の読み取りは0回 |
| API処理 | ダウンロードした実ハンドラーを使い、外部認証／DBを模擬した105件の確認。実際のHTTP侵入テスト105件という意味ではありません |
| 本番DB・復元 | 一時データだけを使用して、変更前コピー、削除前コピー、150問復元、非公開復元、競合拒否、オーナー限定、アカウント消去時の整理を確認。すべてロールバック |
| 本番DB・権限 | 生きた認証セッション、個人デッキの他人への読み書き拒否、管理者の追加認証、役割偽装、SQL風の入力、自動防御の条件を確認。一時データはロールバック |
| 本番DB・フィードバック | 追加認証前の管理者を拒否、自分の送信内容は維持、確認済み管理者を許可、無効化済みセッションを拒否 |
| 本番DB・旧編集API | 予約メンテナンス中のオーナー以外のstatus/list/requestを拒否。現在の関数定義も確認 |
| 公開ブラウザー | 新しい復元画面の配信、追加認証後のオーナーによる一覧・更新・復元確認のキャンセル、自動防御画面の表示・更新に合格。ログアウト後は一覧0件・非表示となり、メンテナンスの壁で拒否。かいじの模型読み込みと次駅「甲府」、修正版の地形スクリプトも確認 |

API模擬検査105件の内訳：基本18・フィードバックのセッション27・不正入力36・自動防御24。別に画面の軽量テストを実施しています。

## まだ確認済みにしていないもの

- 今回のクラウドブラウザーではGPUが無効のため、3Dの実画面、全区間の景観、実際の音質、スマホ実端末の操作感は確認していません。Chromeでは `chrome://settings/system`、Edgeでは `edge://settings/system` のグラフィックアクセラレーションとブラウザー再起動の案内が表示されます。
- 17時46分ごろ、オーナーの追加認証も成功しました。実ブラウザーで復元一覧と自動防御の表示・更新、復元確認ダイアログのキャンセルを確認しました。実データは復元していません。検査後はログアウトし、今回のセッション1件の失効をDB側でも確認。復元画面は非表示・一覧0件となり、メンテナンスの壁で拒否されることを確認しました。認証の迂回やパスワード変更はしていません。
- 通常利用全体の通し検査は、以前の指定どおり別工程です。全ゲームの全操作と、動画の全対応コーデック・4K長時間書き出しまで合格したものではありません。
- 古い検査には、追加済み機能以前の比較用データを前提とするものや、この環境にない検査ライブラリー／ブラウザーを要求するものがあります。実行できない検査を合格に書き換えていません。現在の変更は上記の本番DB検査・実データ計算検査・利用可能な回帰テストで確認しました。
- 旧編集APIの古い包括テストは接続側の要求状態エラーで再実行できなかったため、設定を書き換えない拒否検査と関数定義の照合に切り替えました。包括テストが今回合格したとは記録していません。

## セキュリティー診断の注意表示

非公開テーブルの「RLSは有効だが許可ルールなし」は、直接アクセスを拒否する意図した設定です。公開呼び出し可能な関数は、公開状態の照会または内部で権限を確認するAPIです。警告を消すためにアクセス権を広げていません。

漏えい済みパスワードの照合機能は有料プランが必要なため、有効にしていません。

- [RLS診断の説明](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy)
- [公開関数の診断](https://supabase.com/docs/guides/database/database-linter?lint=0028_anon_security_definer_function_executable)
- [パスワード保護の説明](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection)

実アカウント数は検査前後とも3件。一時検査用アカウントは0件です。保守設定やゲームの公開・非公開を、この点検のために一括変更していません。

## 無料対応の追加点検（10月29日・後半）

利用者の指示により、有料必須の項目は実施待ちから除外しました。有料API・Supabase Proの漏えい済みパスワード照合・有料PITR・有料監視・GPUレンタルを再提案しません。過去の実施記録は改変せず残します。現在の予定は `../free-only-maintenance-plan.json` にまとめています。

無料で直せる追加の問題を修正・公開しました。

- 復旧一覧が最新100件で止まる問題を修正。20件ずつ前後へ移動でき、古いコピーにも到達できます。101件のテストで最後のコピーまで確認し、ログアウト後の非表示・遅れて届く応答の破棄も含め17項目に合格しました。
- 素材再接続は種類が合うものだけに限定。保存済みの編集範囲より短い素材では置き換えず、現在のプロジェクトを保ちます。
- 素材の読み込みは30秒で打ち切り、失敗時は一時URLと再生要素を解放します。読み込み中に書き出しが始まった場合も素材を差し込みません。
- BGM・効果音は、読み込みが成功した素材だけをタイムラインへ追加します。失敗したのに既存の別素材を追加したり、成功表示を出したりしないようにしました。
- 上記の素材処理7ケースと、既存のプロジェクト検証15項目、書き出し後片付け4ケースに合格しました。いずれもコードを使った模擬検査で、実コーデックの入出力検査ではありません。

本番の編集画面はオーナーとして開けました。続く素材選択ではブラウザー操作が応答せず、ブラウザー側のタブ・ログイン状態も失われたため、実ファイルの読み込み・書き出しの通し検査は完了していません。アプリの不具合か操作環境の問題かは断定しません。同じ操作を何度も繰り返したり、別の操作手段で制限を迂回したりしていません。無料の検査がすべて完了したという記録にはしていません。
