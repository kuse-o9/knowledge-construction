# 重要情報・失効セッション・保存荒らしの追加保護
実施：2026年10月30日。追加の有料サービス・AI・プラン変更なし。

## 本番に反映した修正
1. Data APIの認証済み要求でもauth.sessionsの存在・利用者との一致・not_afterを照合。利用停止中のアカウントも拒否。古いJWTが署名上は有効でも、失効したセッションならHTTP401で拒否する。
2. オーナー／管理者の状態照会と個人プロフィールのアクセス判定にも有効セッションを要求。
3. ゲームのクラウドセーブに有効セッションを要求するRESTRICTIVE RLSを追加。ゲームは従来どおり勉強アプリのメンテナンスによる停止対象外だが、ログアウト・利用停止は反映する。資源受け取りRPCも同じ条件を確認する。
4. ゲーム保存データは1件8MiBまで、保存IDは128文字まで。1アカウント256保存枠まで。新しい保存枠の同時作成はアカウント単位のトランザクションロックで競合を抑える。既存枠へのupsertは上限時も可能。DB全体400MiB超過時は新規保存／増加更新を拒否し、減量更新は許す。既存データを自動削除しない。全体容量判定は厳密な予約容量計算ではなく、同時処理分の増加や他の経路の保存は別に考慮が必要。
5. オーナーのメンテナンス設定画面は、ログアウト・権限降格で設定欄を消去。ログアウトより前の読取／変更通信が後から完了しても、設定内容を再表示しない。
6. 前段で導入済みのData API全体6件／アカウント2件／オーナー専用1件の同時実行枠は維持する。

## 検査と結果
- 本番DB：存在しないセッションを持つオーナー相当のclaimsを検査用トランザクション内だけで設定。owner/admin/adminVerified=false、プロフィール許可false、APIはPT401、セーブ閲覧0件、資源受け取り拒否、auth.usersと管理者パスワード保存表の直接閲覧拒否を確認。全体をROLLBACK。
- 本番DB：既存の有効セッション18件を内部で照合し、live_sessionがすべてtrueになることを確認。ID・トークンは出力・公開しない。ログイン画面の通し確認を行った意味ではない。
- 本番DB：8MiB超の置換入力は保存トリガーで54000拒否。例外検査を含む全体をROLLBACKし、元データを変更していない。
- 本番DB：UUID付きの一時保存枠を同じアカウントに作成するトランザクション検査。合計256枠で追加を拒否し、既存枠のupsertは成功。すべてROLLBACK。
- 検査後の既存セーブは1件・1140バイトのまま。
- 実公開REST：匿名の状態照会HTTP200、owner/adminVerified=false、password_hashキーなし。
- 模擬UI：ログアウト時の欄消去、遅延した読み取り／変更応答の破棄、権限降格、非オーナーの非表示を確認。既存の自動防御UI10項目・復元UI17項目も合格。
- 手元のソース324ファイル（対象拡張子・2MB以下、依存パッケージ除外）を既知のOpenAI秘密キー・Supabase秘密キー・秘密鍵の文字パターンで検査し、一致なし。公開中の全ファイル・全履歴・未知の秘密形式まで漏えいがないことを保証する検査ではない。
- セキュリティアドバイザーでは認証済み実行可能なSECURITY DEFINERの注意が1件増加。study_live_accountは本人の利用可否booleanだけを返し、秘密・他人のデータを返さず、固定search_path、匿名実行不可。RLSを迂回してデータを返すAPIではない。既存の意図したRLS拒否設定や有料パスワード漏洩検査の注意は変更していない。
- auth.users/auth.sessionsの一時追加を含む包括検査2回は接続のInvalid or expired requestStateにより実行を確認できず、合格扱いにしていない。既存データを書き換えないセッション照会・権限拒否検査と、ROLLBACKで戻すセーブ検査に切り替えた。
- 初期マイグレーションのSQL区切り誤りはトランザクション失敗を修正してから適用。途中状態を成功扱いにしていない。

## 検証ツールと重要情報について
利用者のブラウザーに渡したJavaScript、画面の内容、本人の認証用アクセストークンは、本人が検証ツールで確認できる。検証ツールの無効化やコードの難読化で秘密を保護する方式は使わない。
サーバーの秘密鍵・管理者用パスワードのハッシュ・他人の個人情報をブラウザーに送らず、サーバーで権限確認する。公開用publishableKeyは秘密鍵ではなく、RLSと認可を前提に公開する値。
本人の端末に既に表示／取得された情報を、ログアウト後に遠隔で完全消去する保証はできない。端末そのものへの不正操作や拡張機能による窃取も別の問題。
今回の変更はすべての攻撃を防ぐ保証ではない。Auth・Storage・Realtime・静的配信を含むDDoSを無料で完全防止するものではなく、物理実機・全画面・全ログイン操作を再確認したものでもない。
