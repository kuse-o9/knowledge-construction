# 機能・画質を保つ処理軽量化（2026-10-20）

比較元：`e930e7d78211eb23718e3b3413d229f3ef767321`。対象は既存の鉄道ゲーム共通処理と車両基地。

## 変更内容

- 線路の閉塞検索を二分探索に変更し、列車が重なり得る区間だけを調べる。信号判定が既に持つ在線一覧を再利用し、同じ一覧を信号ごとに作り直さない。
- 周辺路線の元のサンプル点を空間索引へ登録する。元と同じ点・距離式・範囲で判定し、遠い点の全件走査を省く。近接線路の模型を作る位置も同じ点を選ぶ。
- 基地で人物とエレベーターの形が変わらない時は、既存のGPUバッファを再利用する。視点だけを動かすたびの模型作成・転送を省く。プログラムの属性/変数の位置と色の基礎値も再利用する。

解像度、描画倍率、模型の頂点、法線、色、地形、街の表示範囲、列車数、信号、安全制御、シミュレーション更新間隔、各操作・案内は削減しない。基地の描画回数も変えない。

## 測定

Node v24.19.0、同じ入力で5回測った中央値。ゲーム全体のFPSやユーザー端末の速度倍率ではない。

|処理|変更前|変更後|計算の速度比|
|---|---:|---:|---:|
|周辺路線検索 5,000回|351.0ms|24.6ms|約14.3倍|
|在線判定 1,000回|232.7ms|42.5ms|約5.5倍|
|AI列車更新 100回|1,891.2ms|536.2ms|約3.5倍|

実ブラウザの基地で同じ状態を24回描き直した場合、GPUへの模型転送は48回・393,984バイトから0回・0バイトになった。描画命令はどちらも72回。模型が動くときは必要な転送を行う。

## 同じ結果の確認

- `runtime.test.js`：1,500ケースの在線判定と境界値、既存線路の近傍検索、AIの状態推移、全区間の信号/制動出力を旧実装と比較。
- `depot-equivalence.test.js`：613回の描画でGPUへ渡す模型・色・カメラ・高さが一致。歩行、階移動、コンテキスト復旧を含む。
- `browser-compare.cjs`：実際のChromium/ANGLE SwiftShaderで通常視点と周回後のスクリーンショットを比較。両視点とも異なるピクセルは0。ブラウザエラー/GLエラーなし。
- `visual-data-invariance.json`：4ゲームの模型・街・線路データ、物理/音声/画面のスクリプトと他のパケットフィールドが同一。
- `tests.log`：既存機能を含む65テストが通過。

物理GPUでのFPSは未測定。鉄道全線の全カメラ画像をピクセル比較したという意味ではない。線路や表示設定を変更せず、計算結果の一致と保持データの一致で検査している。

## 再実行

```
node --test development/performance/runtime.test.js development/performance/depot-equivalence.test.js
node development/performance/benchmark.cjs
BAYLINE_CHROMIUM=/path/to/chrome node development/performance/browser-compare.cjs
```

ブラウザ検査はPlaywrightを使う。`baseline/` は比較元コミットの処理スクリプトを固定した検査用資料で、ゲームから読み込まない。ベンチマークと検査結果JSONも同じ場所へ保存する。
