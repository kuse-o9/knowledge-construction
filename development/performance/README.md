# 3D運転の負荷軽減

`3d-release.json` に不変の元パケットのSHA-256を記録。従来の圧縮模型パケットは置き換えず、共通ローダーが照合後に読み込む。修正する共通処理・運転処理は外部スクリプトとして読み込む。

- 解像度・模型・乗客数・機能を減らさない。展開済みジオメトリーは64 MiBのLRUキャッシュとし、不要になった展開結果を破棄する。元データや表示模型を削らない。
- 地形切り抜きはプレイヤー近傍だけ作成する。トンネルの床・壁・屋根・照明は同じ位置・同じ形状を維持し、窓が移動しても重なる部分を再利用する。
- 変化していない乗客の変換行列と編成の表示フラグを再設定しない。
- 地域の写真地図を全球ベースの上に重ね、Cesium 1.117の背景地図端部の交差判定エラーを避ける。
- ローダーの失敗時に再試行できる。描画停止時は一時停止・保存し、「3Dを再読み込み」から運転記録を保って再試行する。

`runtime-regression.test.cjs` はキャッシュ上限と、トンネル窓を移動した後の全表示形状の一致を検査する。検査用条件では作り直すEntityが918→84、834個を再利用。これは実機FPSの測定値ではない。

`3d-validation.json` は5路線14場面の実ブラウザー・ソフトウェアWebGL検査とCPUプロファイルを記録する。元から地下区間のない初期ルートは地上の運転席・車外を検査。画質設定は既存の値を維持。

ビルド：`python development/tools/build-performance-release.py`。既存模型パケットから、検査した外部運転処理と軽い入口ページを再生成する。山手線は通常の外部ソースを直接更新する。
