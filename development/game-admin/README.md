# ゲーム公開管理の導入

1. 既存のSupabaseプロジェクトのSQL Editorで `game-publication.sql` を実行する。既存の `study_dispatch` を利用し、既存のアカウント・デッキのテーブル/関数は置き換えない。
2. オーナーまたは管理者アカウントで `study_game_admin` の一覧取得が成功し、一般利用者が拒否されることを確認する。
3. `config.js` の `gamePublicationEnabled` を `true` にして公開する。DB適用前に有効にしない。
4. 管理者ページの「ゲーム」から開く。非公開→別の通常画面から起動停止→公開→再起動、他の管理者との同時更新を確認する。

公開範囲はゲーム一覧と通常のゲーム起動を制御するもの。GitHub Pages上の静的ファイルや公開リポジトリのコードを秘密にするアクセス制限ではない。実行中のゲームは最長30秒程度で停止する。

追加機能：ゲーム名検索、公開状態の絞り込み、お知らせ（160文字）、直前設定への取り消し、更新の競合検出。管理者・オーナーはオーナー申請なしで変更できる。一般利用者と未ログイン利用者の変更をDBで拒否する。

2026-10-22に本番SQL適用と本番DBでの権限・切り替え・競合・取り消し検査を実施。検査の変更はROLLBACK。匿名HTTPでカタログ200/7件、管理RPC401/42501を確認し、公開設定を有効化。SQL内の認証claim検査と、利用者の実ログイン操作検査は区別する。

検査：実際のSQLをPostgreSQL（PGlite）で実行し、既存の管理者認証関数だけをテスト用フィクスチャにした権限・競合・取り消し検査を実施。フロント画面はRPC通信をモックして検査。本番DBの合格記録とは区別する。
